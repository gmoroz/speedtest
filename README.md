# speedtest

Утилита принимает URL ресурса и последовательно скачивает его заданное число раз. Она считает среднее время запроса, объём полученных данных и скорость загрузки в МБ/с — это покрывает требования задания про 10 последовательных запросов к тяжёлому ресурсу.

## Требования

- Python 3.14
- [uv](https://docs.astral.sh/uv/)
- `make`, `git` и Node.js с `npm` — для `make install` и проверок разработки (`npm` ставит `jscpd`); для запуска
  через `uv sync` они не нужны

## Установка

Из корня репозитория:

```bash
make install
```

Или установи зависимости Python CLI напрямую:

```bash
cd speedtest
uv sync
```

## Запуск

Из корня репозитория перейди в каталог CLI и передай URL ресурса:

```bash
cd speedtest
uv run speedtest https://upload.wikimedia.org/wikipedia/commons/3/3f/Fronalpstock_big.jpg
```

То же измерение через модуль Python:

```bash
uv run python -m speedtest https://upload.wikimedia.org/wikipedia/commons/3/3f/Fronalpstock_big.jpg
```

По умолчанию выполняются 10 последовательных запросов. Число запросов можно изменить опцией `-n` или `--requests`:

```bash
uv run speedtest --requests 3 https://upload.wikimedia.org/wikipedia/commons/3/3f/Fronalpstock_big.jpg
```

Wikimedia ограничивает частоту загрузок: при нескольких запусках подряд сервер может ответить `HTTP 429`, и замер
остановится с подсказкой. Повтори позже или передай URL другого тяжёлого файла.

Справка по аргументам:

```bash
uv run speedtest --help
```

## Пример вывода

Числа зависят от канала, сервера и текущих условий сети.

```text
$ uv run speedtest https://upload.wikimedia.org/wikipedia/commons/3/3f/Fronalpstock_big.jpg

Запросов: 10, последовательно

 1/10  14.68 МБ за 1.117 с
 2/10  14.68 МБ за 0.551 с
 3/10  14.68 МБ за 0.555 с
 4/10  14.68 МБ за 0.551 с
 5/10  14.68 МБ за 0.549 с
 6/10  14.68 МБ за 0.584 с
 7/10  14.68 МБ за 0.549 с
 8/10  14.68 МБ за 0.550 с
 9/10  14.68 МБ за 0.550 с
10/10  14.68 МБ за 0.551 с

Среднее время запроса: 0.611 с
Скачано: 146.79 МБ (в среднем 14.68 МБ за запрос)
Скорость: 24.04 МБ/с (1 МБ = 1 000 000 байт)
```

Первый запрос дольше остальных (почему — в следующем разделе). Разовая сверка на том же канале: `curl` скачал те же
14 679 474 байт (совпадает с `Content-Length`) за ~1.12 с. Это близко к первому запросу: `curl` каждый раз открывает
новое соединение.

## Как считается скорость

- Время одного запроса измеряется от отправки `GET` до получения последнего байта тела ответа.
- Первый запрос включает установку TCP/TLS-соединения. Следующие запросы переиспользуют keep-alive-соединение, если
  сервер его не закрывает.
- В объём входят байты тела ответа без распаковки `Content-Encoding`; заголовки и служебные данные протокола не считаются.
- Редиректы выполняются: в объём попадает только тело итогового ответа, а во время — и промежуточные запросы.
- Запросы выполняются строго последовательно.
- Скорость рассчитывается так: `суммарный объём / суммарное время`, что эквивалентно `средний объём / среднее время`.
- В расчётах `1 МБ = 1 000 000 байт`.

## Конфигурация

Настройки читаются из переменных окружения и файла `.env` в текущем каталоге:

| Переменная | Назначение |
|---|---|
| `SPEEDTEST_REQUEST_COUNT` | Число последовательных запросов; опция `-n` важнее |
| `SPEEDTEST_TIMEOUT_SECONDS` | Сколько секунд ждать данных от сервера: соединения, ответа, очередной порции тела |

Значения по умолчанию заданы в `speedtest/src/speedtest/const.py`. Шаблон — `speedtest/.env.example`: скопируй его в
`speedtest/.env` и раскомментируй нужные строки. Число запросов должно быть не меньше 1, таймаут — больше 0 и не
больше 3600 с. Значение вне этих границ или не число даёт сообщение `Ошибка конфигурации: <переменная>: <причина>` и
код выхода `1`. `--help` и `--version` работают и при сломанной конфигурации.

## Ошибки и коды выхода

- `0` — замер завершён успешно.
- `1` — ошибка замера (некорректный URL, сетевая ошибка, таймаут, не-2xx-ответ, пустое тело, `-n` меньше 1) или ошибка конфигурации. Сообщение печатается в `stderr`; при некорректных URL и числе запросов в `stdout` ничего не выводится. Закрытый `stdout` (например, `| head -1`) тоже даёт `1`, без сообщения и traceback. Пароль из URL в выводе заменяется на `***`.
- `2` — ошибка аргументов командной строки `argparse`.
- `130` — замер прерван сочетанием `Ctrl+C`.

## Структура

Код лежит в `speedtest/src/speedtest/`. `cli.py` разбирает аргументы, создаёт HTTP-клиент из `clients/` и передаёт его
сервису из `services/`. Сервис считает замер и знает о загрузчике только через `Protocol`, поэтому от `clients/` не
зависит. Таблица слоёв, запреты и устройство тестов — в [speedtest/AGENTS.md](speedtest/AGENTS.md).

## Проверки

Полный набор проверок: `ruff`, `mypy` в строгом режиме, `vulture`, `import-linter` и `pytest` с порогом coverage:

```bash
make full-check FULL=1
```

Без `FULL=1` локальный `make full-check` проверяет только части проекта, изменённые относительно upstream, и печатает
пропущенные проверки. GitHub Actions всегда запускает полный набор: `make install` и `make full-check`.

`make lint` сначала форматирует код (`ruff check --fix`, `ruff format`) и только потом проверяет, поэтому может изменить
файлы.
